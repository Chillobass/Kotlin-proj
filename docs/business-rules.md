# TenderHub — бизнес-логика

Клиент-серверное приложение на Kotlin для проведения закрытых тендеров. Заказчик публикует потребность («нужно поставить 500 ноутбуков», «нужно отремонтировать офис»), исполнители подают заявки, по истечении срока система ранжирует заявки и публикует итоговый рейтинг.

## Зачем это нужно

- **Заказчику** — быстро собрать конкурентные предложения и выбрать лучшее по прозрачным, заранее известным критериям, а не «по знакомству».
- **Исполнителю** — найти заказы и участвовать в них на равных условиях: правила оценки известны заранее, чужие ставки до закрытия не видны.
- **Площадке (админу)** — не пропускать мусорные, мошеннические и некорректные тендеры.

Ключевые принципы:
1. **Модерация на входе** — тендер попадает на площадку только после проверки админом.
2. **Закрытые заявки** — пока тендер открыт, никто не видит чужих предложений.
3. **Автоматическая и прозрачная оценка** — рейтинг считается по формуле, известной всем участникам до подачи заявки.
4. **Публичность итогов** — после закрытия рейтинг доступен всем пользователям.

## Роли

| Роль | Что может |
|---|---|
| **Пользователь (USER)** | Подавать заявку на создание тендера, участвовать в чужих тендерах, просматривать открытые тендеры и итоги закрытых |
| **Администратор (ADMIN)** | Модерировать заявки на создание тендеров, отменять тендеры, блокировать пользователей |

- Один и тот же пользователь может быть и заказчиком, и исполнителем — в разных тендерах.
- Админ не создаёт тендеры и не участвует в них (конфликт интересов).
- Регистрация — только как USER. ADMIN назначается вручную (через конфиг/БД).

## Основные сущности

### Тендер (Tender)

| Поле | Описание |
|---|---|
| `title` | Название |
| `description` | Описание потребности, требования к исполнителю |
| `category` | Категория (IT, строительство, поставки, услуги, …) |
| `maxPrice` | Начальная (максимальная) цена — дороже предлагать нельзя |
| `deadline` | Дата и время закрытия приёма заявок |
| `criteria` | Веса критериев оценки (см. «Рейтинг») |
| `owner` | Пользователь-заказчик |
| `status` | Текущий статус (см. жизненный цикл) |
| `rejectionReason` | Причина отклонения/отмены (если есть) |

### Заявка на участие (Bid)

| Поле | Описание |
|---|---|
| `tender` | Тендер |
| `participant` | Пользователь-исполнитель |
| `price` | Предлагаемая цена |
| `deliveryDays` | Срок выполнения, в днях |
| `warrantyMonths` | Гарантия, в месяцах |
| `comment` | Комментарий / описание предложения |
| `submittedAt` | Время подачи |
| `status` | `ACTIVE` / `WITHDRAWN` |

## Жизненный цикл тендера

```
            ┌─────────────┐  админ отклонил   ┌──────────┐
 создание → │ ON_REVIEW   │ ────────────────→ │ REJECTED │
            └─────┬───────┘                   └────┬─────┘
                  │ админ одобрил                  │ владелец исправил
                  ▼                                │ и отправил повторно
            ┌─────────────┐ ←──────────────────────┘ (→ ON_REVIEW)
            │    OPEN     │ ── отмена ──→ CANCELLED
            └─────┬───────┘
                  │ наступил deadline
                  ▼
     есть заявки? ─ да ─→ COMPLETED (рейтинг опубликован, победитель определён)
                  └ нет ─→ FAILED (тендер не состоялся)
```

| Статус | Значение |
|---|---|
| `ON_REVIEW` | Ожидает модерации, виден только владельцу и админам |
| `REJECTED` | Отклонён админом с указанием причины; владелец может исправить и отправить заново |
| `OPEN` | Опубликован, принимаются заявки |
| `CANCELLED` | Отменён до закрытия |
| `COMPLETED` | Закрыт, рейтинг опубликован |
| `FAILED` | Закрыт без единой заявки |

## Бизнес-правила

### Создание тендера
1. Любой незаблокированный пользователь может отправить заявку на создание тендера.
2. Обязательные поля: название, описание, категория, `maxPrice > 0`, `deadline`, веса критериев.
3. `deadline` должен быть не раньше чем через **24 часа** и не позже чем через **90 дней** от момента отправки.
4. Сумма весов критериев = 100%, каждый вес ≥ 0.
5. Одновременно у пользователя может быть не более **5** тендеров в статусе `ON_REVIEW` (защита от спама).

### Модерация
1. Админ одобряет или отклоняет тендер. Отклонение — только с указанием причины.
2. На момент одобрения до `deadline` должно оставаться не менее **24 часов**. Если модерация затянулась и времени не хватает — админ не может одобрить, тендер отклоняется с причиной «перенесите срок».
3. После одобрения тендер сразу переходит в `OPEN` и становится виден всем.
4. Отклонённый тендер владелец может отредактировать и отправить повторно — он снова попадает в `ON_REVIEW`.
5. Тендер в `ON_REVIEW` владелец может редактировать или отменить (физически тендеры не удаляются — остаётся история).

### Открытый тендер
1. После публикации условия тендера (цена, срок, критерии) **менять нельзя** — участники подают заявки, опираясь на них.
2. Владелец может отменить тендер, **только пока на него нет ни одной активной заявки**.
3. Админ может отменить тендер в любой момент до закрытия (например, выявлено мошенничество) — с указанием причины. Участники получают уведомление.

### Заявки на участие (автоматическая валидация)
Заявка принимается, только если выполнены все условия:
1. Тендер в статусе `OPEN` и `deadline` ещё не наступил.
2. Участник — не владелец тендера и не заблокирован.
3. У участника нет другой активной заявки на этот тендер (**одна заявка от участника**).
4. `0 < price ≤ maxPrice`.
5. `deliveryDays ≥ 1`, `warrantyMonths ≥ 0`.

Если хотя бы одно условие нарушено — заявка отклоняется сразу с понятным сообщением об ошибке.

**Поданная заявка окончательна:** изменить или отозвать её нельзя. Статус `WITHDRAWN` заявка получает только автоматически — если участника заблокировали до закрытия тендера.

### Видимость
| Что | Пока тендер `OPEN` | После закрытия |
|---|---|---|
| Условия тендера | все | все |
| Количество заявок | все | все |
| Содержимое заявок | только автор своей заявки | все (в составе рейтинга) |
| Рейтинг | никто (даже владелец и админ) | все |

Скрытие рейтинга от владельца и админа до закрытия исключает слив информации «своему» участнику.

### Закрытие
1. Закрытие выполняется автоматически планировщиком на сервере в момент `deadline` (время — по серверу, хранится в UTC).
2. Заявки, пришедшие после `deadline`, отклоняются, даже если на клиенте время ещё не вышло.
3. При закрытии рассчитывается и фиксируется рейтинг; после этого он больше не пересчитывается.

### Блокировка пользователей
1. Админ может заблокировать пользователя с указанием причины.
2. Заблокированный не может создавать тендеры и подавать/менять заявки, но может просматривать площадку.
3. Его активные заявки в открытых тендерах отзываются, его тендеры в `ON_REVIEW`/`OPEN` отменяются.

## Рейтинг заявок

Каждая заявка оценивается по трём критериям. Для каждого критерия считается нормированный балл от 0 до 1, затем — взвешенная сумма с весами, которые задал заказчик.

| Критерий | Лучше, когда | Нормированный балл |
|---|---|---|
| Цена | меньше | `minPrice / price` |
| Срок выполнения | меньше | `minDeliveryDays / deliveryDays` |
| Гарантия | больше | `warrantyMonths / maxWarrantyMonths` (0, если у всех 0) |

`min`/`max` берутся среди всех активных заявок тендера.

```
score = wPrice · pricePoints + wDelivery · deliveryPoints + wWarranty · warrantyPoints
```

Итоговый балл — от 0 до 100, округляется до сотых. Заявки сортируются по убыванию балла.

**При равенстве баллов** выше та заявка, что подана раньше.

**Победитель** — заявка на первом месте рейтинга.

Пример: веса цена 60%, срок 30%, гарантия 10%.

| Участник | Цена | Срок | Гарантия | Балл |
|---|---|---|---|---|
| A | 900 000 | 30 дн | 12 мес | 60·1.00 + 30·0.67 + 10·1.00 = **90.0** |
| B | 1 000 000 | 20 дн | 6 мес | 60·0.90 + 30·1.00 + 10·0.50 = **89.0** |
| C | 950 000 | 40 дн | 12 мес | 60·0.947 + 30·0.50 + 10·1.00 = **81.84** |

## Уведомления (внутри приложения)

- Владельцу: тендер одобрен / отклонён / отменён админом; тендер закрыт, есть итоги.
- Участнику: тендер, где есть его заявка, отменён / закрыт; занятое место в рейтинге.
- Админам: появился новый тендер на модерации.

---

## Основные сценарии

1. **Пользователь создаёт тендер** → заполняет форму → тендер `ON_REVIEW` → админ одобряет → `OPEN`.
2. **Пользователь ищет тендеры** → список открытых с фильтрами по категории, цене, сроку → карточка тендера → подаёт заявку.
3. **Участник подаёт заявку** → она проверяется автоматически и больше не меняется.
4. **Тендер закрывается** → планировщик считает рейтинг → все видят результаты, победитель отмечен.
5. **Админ** → очередь модерации → одобрить / отклонить с причиной; управление пользователями.

---

## Что не входит в первую версию

- Оплата, договоры, электронная подпись.
- Переговоры и чат между заказчиком и участниками.
- Многоэтапные тендеры и переторжка.
- Загрузка файлов (документация к тендеру).
